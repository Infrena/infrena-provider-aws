# S3

Amazon S3 (Simple Storage Service) is a scalable, object storage service. S3 buckets store objects (files) and can be configured with versioning, lifecycle policies, encryption, and access controls. Bucket policies control who can access the bucket and its objects.

## Bucket

An S3 bucket is a container for objects. Buckets are regional resources — they belong to a specific AWS region. You can enable versioning, set encryption, configure lifecycle rules, block public access, and apply tags to buckets.

**Type:** `aws.s3.bucket`

**Import ID:** `<region>/BucketName`

**Settable attributes:**
- `name` (alias for `BucketName`): the name of the bucket (must be globally unique across all AWS accounts)
- `region`: the AWS region for the bucket (inherited from provider defaults if not specified)
- `versioning_configuration`: a map with `Status` set to `Enabled` or `Suspended` to enable versioning
- `lifecycle_configuration`: a map defining lifecycle rules for object expiration and transitions
- `bucket_encryption`: a map defining server-side encryption (SSE-S3, SSE-KMS, or DSSE-KMS)
- `public_access_block_configuration`: a map to block public access (recommended for security)
- `tags`: a map of tags

Example:

```yaml
  app_bucket:
    type: aws.s3.bucket
    name: app-data-bucket-prod
    region: us-east-1
    versioning_configuration:
      Status: Enabled
    bucket_encryption:
      Rules:
        - ApplyServerSideEncryptionByDefault:
            SSEAlgorithm: AES256
    public_access_block_configuration:
      BlockPublicAcls: true
      BlockPublicPolicy: true
      IgnorePublicAcls: true
      RestrictPublicBuckets: true
    tags:
      Environment: production
      Application: data-pipeline
```

## Bucket Policy

A bucket policy is a resource-based policy attached to an S3 bucket. It defines what actions principals (users, roles, services) can perform on the bucket and its objects. Bucket policies are written as JSON and control access at the bucket level.

**Type:** `aws.s3.bucketpolicy`

**Import ID:** `<region>/Bucket`

**Settable attributes:**
- `bucket`: the name of the bucket the policy applies to (required)
- `policy_document` (alias for `PolicyDocument`): the policy document as a JSON string
- `region`: the AWS region (inherited from provider defaults if not specified)

Example:

```yaml
  app_bucket_policy:
    type: aws.s3.bucketpolicy
    bucket: app-data-bucket-prod
    policy_document: |
      {
        "Version": "2012-10-17",
        "Statement": [
          {
            "Effect": "Allow",
            "Principal": {
              "AWS": "arn:aws:iam::123456789012:role/app-role"
            },
            "Action": ["s3:GetObject", "s3:PutObject"],
            "Resource": "arn:aws:s3:::app-data-bucket-prod/*"
          }
        ]
      }
    region: us-east-1
```

## Common patterns and pitfalls

- **Bucket names are globally unique.** Every S3 bucket name must be unique across all AWS accounts and regions. Choose a distinctive name that includes your organization or project identifier.
- **Versioning is immutable in CloudFormation.** Once versioning is enabled on a bucket, you cannot disable it — you can only suspend it. If you suspend versioning, existing object versions are retained; new objects do not have versions.
- **Public access block is recommended.** For security, enable all four options in `public_access_block_configuration` (`BlockPublicAcls`, `BlockPublicPolicy`, `IgnorePublicAcls`, `RestrictPublicBuckets`) unless you have a specific reason to allow public access.
- **Bucket policies are JSON strings.** Like IAM policies, bucket policies are written as JSON text in YAML block strings (`|` or `|-`). This preserves the exact JSON.
- **Lifecycle rules use ISO 8601 dates.** When defining lifecycle rules for expiration or transition, use ISO 8601 format for dates (for example, `2024-12-31`).
- **Encryption applies to new objects.** Server-side encryption configured in `bucket_encryption` applies to objects uploaded after the configuration is applied. Existing objects are not automatically re-encrypted.
- **Regional resource.** S3 buckets are regional. The bucket's region is specified in the resource configuration or inherited from the provider's default region.
